Connecting

From a phone, a computer, or both at once

The board has no screen; you use it from a browser. There are three ways in, and all three show the same interface — which one you use depends on whether you have a computer and how precise the measurement needs to be.

Which one should I pick?

SituationModeAddress
No computer, just a phone 1 · The board's own network 192.168.4.1
Home Wi-Fi available, board elsewhere in the house 2 · Board on the home network http://olcum.local
Computer available, measurement isolated 3 · USB bridge http://olcum.localhost:8770 (this computer only)
USB can't be used for every measurement — but Wi-Fi alone isn't enough either. The board is not isolated: with USB plugged in, the board's ground is your computer's ground, so on a mains-referenced circuit (such as the primary side of a non-isolated SMPS) you bring mains voltage to your computer.

Floating it on battery + Wi-Fi saves the computer, NOT YOU: the board rises to mains potential and every point on the board becomes dangerous. For this measurement an insulated enclosure is a must, and nobody touches the board while it is live. Details in the warning at the top of the Assembly page.
Why is the USB bridge recommended (when it fits)? Every browser connected to the board slows the measurement down a little — the board both measures and runs a web server. In bridge mode the computer serves the page and the measurements are archived on the computer, so the board's memory doesn't fill up.

⚠ The board's Wi-Fi doesn't switch itself off. It is on by default; to turn it off send N0 from the serial console (to turn it back on: N1). With it off, the measurement loop never deals with the web server at all.

1 · Without a computer — the board's own network

If no home Wi-Fi is configured when the board starts (or it can't connect within 10 seconds), it sets up its own Wi-Fi network:

Network nameOLCUM-KARTI-XXXX — the last four characters are the board's own ID, different on every board
Password12 characters, generated by the board on first start and printed to the USB console. Read it once and save it on your phone
Address192.168.4.1 — fixed

When the phone joins this network there is no internet (the board doesn't go online); Android may ask "this network has no internet, stay connected?" — say yes.

2 · Board on the home network

Instead of setting up its own Wi-Fi, the board joins the home network; the phone and computer are already on it. It tries to connect for 10 seconds, and if that fails it falls back to mode 1 — so the board is never left unreachable. While on its own network it retries the home network every 30 seconds: if the home network appears later (e.g. after a power cut, when the router comes up after the board), the board moves home by itself and closes its own network 5 seconds later — no reset needed. If the network drops briefly while connected, the board reconnects by itself; if it is gone for more than 30 seconds (e.g. you took the board somewhere else) it sets up its own network and retries the saved networks immediately, then every 30 seconds.

Telling the board about networks (up to 8)

The board remembers up to 8 networks (home, work, your phone's hotspot …). At start-up it tries the network it last connected to; if that's not there, it picks a preferred one among the visible saved networks, then the one with the strongest signal. The easiest way is Settings → Network in the panel: Refresh list, Scan networks, add, make preferred, Delete, “Switch to this network”. The same from the serial console (115200):

NaNetworkName + NppasswordAdd to the list (if the name exists it is selected; Np sets the password of the last one added)
Nl · NtList saved networks · scan for nearby networks (no password appears in any output)
NgnoSwitch to this network: the board looks for the network first and doesn't leave if it can't see it; if it can't connect within 20 seconds it goes back to the previous network
Nono · NxnoToggle preferred · delete (deleting the connected network doesn't drop the connection)
NPrints the status: mode, SSID, IP, mDNS, number of saved networks

The settings live in the board's non-volatile memory; you don't have to enter them again. On your phone's hotspot list the board shows up under its own network name (OLCUM-KARTI-XXXX).

Addresshttp://olcum.local
If that failsThe board's IP is printed on the USB console (N command); type it in directly. On Android .local is not reliable — on iPhone and desktop it works fine
How many people can watch at once? Connected directly, the board serves up to 4 browsers; each one slows the measurement a little. The PC bridge takes one of these slots when it is connected to the board over Wi-Fi, and none over USB. If you want more viewers, use mode 3.

3 · USB bridge — on the computer; the phone only watches

The board connects to the computer over USB, and a small program runs on the computer (PC Baslat.bat in the kopru folder). That program both serves the interface and records the measurements. To stop it, use Kopruyu Durdur.bat in the same folder. First pairing, the recordings archive on the computer, notifications and troubleshooting: PC app.

On the computerPanel at http://olcum.localhost:8770 — the bridge listens only on this computer (127.0.0.1); no other device can connect to this address. Port 8770 is fixed: if another program holds it, the bridge doesn't start and says so (it doesn't fall back to another port — the panel's settings on this computer are tied to the address)
On the phoneIf the bridge is started with --lan (PC Baslat.bat --lan), a phone on the same Wi-Fi can watch read-only at http://<computer's IP>:8770: it sees the measurement and can only send STOP (end the battery test). To give commands, the phone connects to the board directly (mode 1 or 2)
Board's Wi-FiOn by default. If you want full measurement speed, turn it off with N0 from the serial console
RecordingEvery measurement row is stored on the computer with a timestamp and can be exported as CSV later

In this mode the page the phone sees is served by the computer, not by the board. The phone and computer can be used at the same time and both see the same data; commands only go from the panel on the computer.

Opening it like an app on the phone

Open the page in the browser and choose Add to Home Screen.

iPhoneOpens with its own icon, without the address bar — no different from an app
AndroidA shortcut is created, but it opens in a Chrome tab. Full-screen install needs HTTPS, and the board has no HTTPS. This is expected behaviour

Where does the interface live?

The whole interface — the page, the Vue library, the stylesheets — is in the board's own memory. No internet is needed and no file is downloaded from outside.

Security — what it protects, what it doesn't

The connection is not encrypted (no HTTPS). Someone on the same network can see the measurements; that is an accepted limit for this board.

On every commandA session key and a custom header are required. This stops another web page from sending commands to the board in your name (CSRF)
PasswordNOT SET by default. Until one is set, anyone on your network can open the board's page and send dangerous commands. The board says so loudly at start-up
Setting the passwordFrom the serial console: Nspassword. To remove it: Ns (empty). N shows the status
The board's own networkThe AP password is generated by the board (12 characters) and printed to the USB console on first start
The one exception: stopping. The command that stops a battery discharge always works — it needs neither the session key nor the password. Safety comes before convenience.
What the password protects against is "someone else at home pressing something by mistake". Without TLS it is not protection against someone listening on the network.
