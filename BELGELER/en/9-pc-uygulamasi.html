PC app

Bridge · archive on this computer · Windows notifications — install, start, use

Panel addressolcum.localhost:8770
Recording syncevery 120 s
Board acknowledgementdefault on
Data folderolcum-karti

The PC app is a single program that sits between the board and this computer (kopru/pc.py; the “bridge”). It does three jobs:

JobWhat it means
BridgeOpens the board's panel on this computer at http://olcum.localhost:8770. Live measurements and commands go over USB if the board is on USB, otherwise over WiFi. The panel is the same one the board serves itself
ArchiveCopies the board's recordings over WiFi to this computer's disk — on every connection and every 120 seconds. The panel's Recordings screen shows this copy
NotificationsIf the board sends notifications to the internet (MQTT), the bridge listens and shows them as Windows notifications — even with the browser closed
The master copy is on the board. The computer only keeps a copy. The board measures and records with the bridge off, too; when the bridge starts it fetches whatever is missing by itself.

1 · First setup — introducing this computer to the board once

For the bridge to talk to the board over WiFi, this computer must be paired with the board. This is done once; the key stays on this computer, stored encrypted and tied to your Windows account.

You needPython installed (python or py) · the board on your home network, with http://olcum.local opening in a browser · the board's web password (at least 12 characters)

Step 0 — already paired?

Type %LOCALAPPDATA%\olcum-karti\cihaz into the File Explorer address bar and press Enter (cihaz = device). If it holds a .json file with a 16-character letters-and-digits name, this computer is already paired: do the check in Step 4 and go on to section 2. If the folder does not exist or is empty, carry on.

Step 1 — stop the bridge if it is running

Double-click projeler\olcum-karti\kopru\Kopruyu Durdur.bat (“stop bridge”). If it says calisan kopru yok (no bridge running), that is fine. (The pairing tool and the bridge use the same key file; if both run at once the board may take the requests for replays and reject them.)

Step 2 — run the command

Open the projeler\olcum-karti folder in File Explorer, type cmd in the address bar and press Enter. In the window that opens:

python kopru/imza.py esles --host olcum.local --ad PC-kopru

--ad is this computer's name in the board's list (at most 24 bytes, anything you like). If python is not found, type the same command with py. If the board is on its own network (not joined to your home network), connect the computer to the board's network and use --host 192.168.4.1.

Step 3 — the password prompt

This prompt appears (it asks for the board's WEB password, NOT the WiFi password, and says it is not echoed):

kartin WEB parolasi (WiFi parolasi DEGIL; ekrana yazilmaz):

Type the board's web password and press Enter. Nothing appears on screen as you type — that is normal, your keystrokes are going through. The password never goes over the network and is not saved anywhere.

Web password ≠ WiFi password. The board has three separate passwords; this one asks for the web password only:
PasswordWhat forHow it is set
Web password ✔Giving commands in the board's panel, and pairing. At least 12 charactersOver USB: Ns<password>
WiFi passwordThe board joining your home network (your router's password) Over USB: Np<password>
AP passwordA phone joining the board's own network The board generates it
The PC bridge has no password of its own: http://olcum.localhost:8770 never asks for a password.

On success the last line looks like this (the number and folder will differ):

eslesti: cihaz 3 (PC-kopru) -> ...\olcum-karti\cihaz\<board ID>.json

If you get an error, see the Troubleshooting table below.

Step 4 — check the board's list

python kopru/imza.py liste --host olcum.local

This prints the board's paired devices (like "ad":"PC-kopru"). If the name you gave is in the list, setup is done. The board holds at most 8 devices; if there is an old entry you no longer use (e.g. an earlier pairing of the same computer), delete it with python kopru/imza.py sil --host olcum.local --n <number> — do not delete your own number (cihaz N in the pairing output).

2 · Starting

Double-click the Ölçüm Kartı shortcut on the desktop (pythonw kopru\pc.py --arka, in the projeler\olcum-karti folder). No console window opens; after a few seconds the panel appears in the browser: http://olcum.localhost:8770. The bridge runs in the background and its icon sits in the notification area at the bottom right of the screen (Show hidden icons ^): hovering shows the connection path (USB / Wi-Fi / searching for the board), double-click opens the panel, right-click → Quit stops the bridge.

If you want to see what is going on, start it with a console via projeler\olcum-karti\kopru\PC Baslat.bat (“PC start”; for debugging):

Installing as an app (Edge)

With the panel open, click the “App available” install icon at the right of Edge's address bar, or Settings and more (⋯) → Apps → Install this site as an app. The panel then opens in its own window, with its icon in the Start menu and on the taskbar. While the bridge is off this window shows the “Bridge not running” page and returns to the panel by itself once the bridge starts.

Sync status line

A single line on the Recordings screen: “Bridge sync: last success … · N new record(s) in the last round · board's last sequence … · acknowledgements on”. On an error it gives the reason and how many seconds until the next try. If the board is on USB only (not on WiFi) the round is skipped: recording data is fetched over WiFi only.

What does acknowledgement mean? Once the bridge has written the recordings to disk for good, it tells the board “these are copied” (default on). When the board's storage fills up it deletes only old recordings that have been copied somewhere; uncopied data is never deleted. So with acknowledgement on, the board may delete old recordings copied to this computer when it needs space — they stay on this computer, but a phone that has not synced yet can no longer see them. If you do not want that, turn acknowledgement off: PC Baslat.bat --onaysiz, or permanently by writing {"esitleme_onay": false} into %LOCALAPPDATA%\olcum-karti\ayar.json (takes effect when the bridge restarts). With acknowledgement off (and no other device acknowledging), the board stops recording when full and sends a notification.

4 · Notifications

The bridge listens to the notifications the board sends to the internet (it only listens, it never publishes) and shows Windows notifications. The source name is Ölçüm kartı (“Measurement board”). For this, the board's notification (MQTT) settings must have been made over USB; otherwise only “no news from the board” (the local path) works.

5 · Options

To pass an option, from the command line: "kopru\PC Baslat.bat" --onaysiz or python kopru/pc.py --onaysiz (in the projeler\olcum-karti folder). If the bridge is already running, the new option is not applied — stop it first.

--arkaDesktop shortcut mode (pythonw): no console, but the panel opens in the browser; notification-area icon — double-click opens the panel, right-click Quit
--tepsiShow the notification-area icon in console mode too

--portSets the COM port by hand (e.g. --port COM6); otherwise the bridge finds the board by its USB bridge chip (CH343)
--kart-hostThe board's WiFi address (default olcum.local). On the board's own network use --kart-host 192.168.4.1, or give the board's IP

6 · Autostart when Windows starts

Installprojeler\olcum-karti\kopru\Otomatik Baslat Kur.bat (“install autostart”) — puts a Olcum Karti PC (arka plan).lnk shortcut into the Startup folder. The bridge then starts in the background at every sign-in (--sessiz: no window, no browser)
RemoveOtomatik Baslatmayi Kapat.bat (“turn off autostart”, same folder). It does not stop a bridge that is running — Kopruyu Durdur.bat does
SettingsThe background bridge takes no options; for acknowledgement and interval use ayar.json ("esitleme_onay", "esitleme_aralik_s")
Install only from the main folder: projeler\olcum-karti. Do not install from temporary branch folders (olcum-karti-…): once that folder is deleted the shortcut points at a missing file and the bridge silently fails to start. The script refuses to run from a temporary branch folder anyway.

The bridge holds the board's COM port. Stop the bridge before uploading firmware, and before using the bench tools, the Arduino Serial Monitor or imza.py — or start the bridge with --usb-yok (then it never holds the port).

9 · Where the files are, what can be deleted

Everything is outside the repository, under %LOCALAPPDATA%\olcum-karti\ (can be typed into the File Explorer address bar). Stop the bridge before deleting anything.

WhatContentsIf deleted
cihaz\Pairing key (device; encrypted, tied to your Windows account) Do not delete. If deleted you must pair again; the old entry stays on the board
arsiv\Copy of the board's recordings (archive; board → stream folders) Careful: with acknowledgement on, the board may have deleted some of these — this may be the only copy. A stream folder you no longer need can be deleted
satir\The bridge's daily line log (live measurement lines; Oscilloscope → Legacy archive reads from here) Can be deleted; recordings (arsiv\) are not affected, the captures in Legacy archive go
bildirim\Encrypted notification-info cache Safe; fetched again while the board is reachable
ayar.jsonOptional settings Safe; defaults come back (acknowledgement on, 120 s, all notifications on)
arkaplan-hata.txtLast crash traceSafe

To move the folder, use the OLCUM_PC_DIZIN environment variable.

10 · Security notes

STOP always worksp0, which stops a battery test, needs no password, signature or pairing; it is the same on the bridge, on a phone (--lan) and on the board
PasswordsType the web password only at imza.py's prompt (not echoed) or into the Pairing form in the board's panel. Never on the command line, in a file, in a chat or in a screenshot. The bridge does not store the password
Local networkBy default the bridge listens on this computer only; even with --lan phones can only watch
E and Q commandsPairing and notification settings change only from the USB serial console; the bridge never forwards them to the board

Optional: making signatures mandatory (Ez1)

By default the board also accepts unsigned requests (the older password path) (E? → zorunlu=0, mandatory=0). With Ez1 the board accepts requests only from paired devices (STOP is still free). It is not required; it only makes sense once every device you use (this computer, phones, browsers — Settings → Pairing) is paired, otherwise an unpaired device cannot reach the board.

1Kopruyu Durdur.bat (or start the bridge with --usb-yok)
2Arduino IDE → Tools → Port: the board's COM port → Serial Monitor, 115200 baud
3Send E?: it prints zorunlu=0 and the list of paired devices — check that you recognise them all
4Send Ez1. To undo: Ez0
5Close the Serial Monitor and restart the bridge
